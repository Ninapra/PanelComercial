# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`PanelComercial` ("Panel de Inteligencia Comercial") is an internal sales/renewals dashboard for **mi.com.co**. The **entire application is a single `index.html`** (~4.8 MB): `<style>` (lines ~8–423), `<body>` markup (~425–716), and one `<script>` (~717–3602). There is **no build system, no dependencies, no backend, and no tests**. The only external network dependency is Google Fonts. All UI text is Spanish (`es-CO` locale).

To run it: open `index.html` in a modern browser (it requires `DecompressionStream`, so Chrome/Edge/Firefox — not older browsers). No server is needed because all data is inlined.

## Data architecture

There is no API. All datasets are embedded in `index.html` as **gzip + base64 string constants**, decompressed in the browser at runtime via `DecompressionStream('gzip')` (see `decompress()` ~727, `regDecompress()`, `getMonth()`, `_dec()` — they are near-duplicate helpers per module).

Consequently **you cannot edit the underlying business data by hand** — it lives compressed on single megabyte-long lines and is regenerated by an external pipeline that is not in this repo (see the `MICOMCO_Renovaciones_v2_Completo.zip` artifact). Edits here are limited to markup, CSS, and JS logic.

Key blob constants (each is one enormous single line — do not try to Read them whole):
- `DATA_B64` (718) → `clientes[]`; `GS_B64` (719) → `globalStats` — Clientes tab
- `MONTH_DATA` (1545) — Renovaciones, lazy-loaded per month by `getMonth(m)` into `CACHE_R`
- `REG_B64` (2267) → `REG_DATA` — Registros tab
- `_DB64`, `_CB64`, `_CCLI_B64` (2671) — Daily tab; `_TB64` — Transferencias tab

Data row shapes:
- **Clientes** records are objects keyed by field name: `'ID Logic'`, `SEGMENTO`, `Categoria`, `SCORE`, `Encargado`, `antiguedad`, `fby` (facturación-by-year), plus per-year metrics `rt{YYYY}`/`rc{YYYY}` (registro monto/count) and `nt{YYYY}`/`nc{YYYY}` (renovación monto/count), and 2025/2026 renewal fields `r25_*`/`r26_*`, `svc25`/`svc26`.
- **Registros / Daily / Transferencias** rows are **positional arrays** (e.g. `r[3]` is the date). Column meaning is by index — trace the render/save functions before touching an index.
- Dates are frequently encoded as **integers `YYYYMMDD`**; convert with `regIntToDate`/`regDateToInt`/`_dateToInt`/`_intToStr`.

## Tab / module structure

Six top-level tabs, each a `.tab-page` div, switched by `showTab(id, el)` (~2157), which **lazily initializes** each module the first time it is opened. Functions are namespaced by a per-module prefix — respect it when adding code:

| Tab | `page-` id | Prefix | Entry point | Persistence (localStorage) |
|-----|-----------|--------|-------------|----------------------------|
| Inicio | `home` | — | `initHome()` | — |
| Clientes | `clientes` | — | `buscar()` → `render(c)`; search `"1"` → `renderGlobal()` | — |
| Renovaciones | `renovaciones` | `r*` | `rRender()` | `mcc_est_v3` (`KEY_R`, via `rEst`) |
| Registros | `registros` | `reg*` | `regInit()`/`regRender()` | `reg_contactos` |
| Daily | `daily` | `d*`, `wa*` | `dInit()` | `mcc_d2` (`_DL`) |
| Transferencias | `transferencias` | `tr*` | `trInit()` | `mcc_t2` (`_TL`) |

Renovaciones/Daily/Transferencias have their own inner sub-tabs (`showSubtab`, `dShowSub`, `trShowSub`). The whole script runs in **global scope** — everything is a global function/variable, so watch for name collisions when adding code.

## Auth (important context, not real security)

A client-side login gate (`lgBuild`/`lgIn`/`lgApply`, ~2590) overlays the page on load. Credentials are **hardcoded in the `_LG` object** (~2588) for three agents — Paula, Camila, Nina — and the session is stored in `sessionStorage._mcu`. This is a soft UI gate only; it provides no real access control (all data is already in the client). The logged-in agent drives Renovaciones agent selection (`rAgente`).

## Working in this file effectively

- **Never Read the whole file** — several lines are multi-megabyte data blobs and will blow the token limit. Read with narrow `offset`+`limit`, or use `grep`/`awk 'NR>=a && NR<=b {print substr($0,1,N)}'`. Avoid blob lines 718, 719, 1545, 2267, 2671.
- SVG charts are generated by string-building helpers (`moneyChart`, `cntChart`, `dualChart`, `donutSVG`, `compCircSVG`, `buildHistorial`).
- Styling is a mix of CSS classes (defined once in `<head>`) and heavy inline `style=` attributes; currency is formatted with `es-CO` `toLocaleString`.
- The dataset is a snapshot pinned to **2026**; some views use hardcoded "today" anchors rather than the real clock.
